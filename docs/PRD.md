# Altitude 产品需求与开发大纲

产品名保持 **Altitude**。亮屏和水印上的拉丁词标比「海拔」更适合被拍进照片；界面文案用中文。曾考虑 Crest，但拍屏幕时画面上需要的是一个一眼能懂的词，而不是一个新品牌。

这不是徕卡相机，也不冒充小米。水印学的是那类底栏签名的排版：照片本体干净，信息落在加出来的纸边上，字距拉开，右侧是主数据，左侧是词标，用一枚红点作记号。不会伪造焦段、光圈或 LEICA 字样。

## 1. 背景

在拉萨到珠峰大本营一带（大约 3,600–5,200 米），人想要两张能发出来的东西：

1. 别人用另一台手机拍你。你把自己的屏幕举起来，上面是一个够大、够稳、在阳光下还能认出来的海拔。
2. 你自己拍风景或人。快门按下之后，海拔和经纬度已经在成片里，而不是事后贴一张截图。

两种都要离线能用。核心读数不依赖网络。

## 2. 目标与非目标

做到：

- 全屏高对比海拔，横竖屏，屏幕常亮，可拉到最高亮度，米/英尺，数字滚动，可选坐标、精度、时间、地名。
- 相机取景和成片使用同一套水印。成片按拍照分辨率重绘，不是截屏。写入相册 `Pictures/Altitude`，并把经纬度与海拔写进 EXIF。
- GPS 椭球高换算成海平面高度。Android 14+ 优先用系统的 `Location.getMslAltitudeMeters()`，否则用随包的 EGM96 15′ 大地水准面。有气压计时，用它做快响应，并用 GPS 海平面高度慢慢校准。
- 定位、相机权限有引导，拒绝之后仍能看说明并再次授权。

不做：

- 账号、云同步、轨迹、地图、社区。
- 伪造镜头参数。
- 离线全球地名库。地名只在系统地理编码可用时出现。
- 把未校准的气压高度标成海拔。

## 3. 场景

| 场景 | 人在做什么 | 成功时看起来怎样 |
| --- | --- | --- |
| 垭口合影 | 一只手举着手机，另一台在拍 | 画面中央是大数字，按钮几秒后隐去，常亮 |
| 营地自拍 / 风景 | 打开相机，确认底栏，按快门 | 相册里的照片下面有白底或黑底签名，EXIF 里有位置和海拔 |
| 没信号的山路 | 飞行模式 | 卫星和气压计仍然出数；地名可以空着 |
| 刚打开、还没有星 | 在屋里等 | 明确写着在找卫星，并给出上次读数，不把 0 当成海拔 |

## 4. 体验原则

- 暗色为底。出片用的五套主题都是高对比，不靠系统动态色来保证可读。动态色如果打开，只影响设置里的控件。
- 数字用 Outfit ExtraBold，等宽数字特性，变化时上下滚一位，而不是整段闪一下。
- 亮屏模式下控件约 4.6 秒后淡出。点一下回来。双击数字切换米/英尺。
- 相机快门有短震动。
- 取景框就是将来的成片比例（竖屏 3:4，横屏 4:3），水印在框里，快门在框外。

## 5. 信息架构

```
首次打开
  └─ 三步引导：亮屏说明 → 定位权限 → 相机权限（可跳过）
主界面
  ├─ 亮屏
  └─ 相机
设置（从两种模式都能打开）
  单位、主题、最高亮度、亮屏上的附加信息、水印样式
```

两种模式用同一个「亮屏 / 相机」切换，不做深层导航。

## 6. 功能说明

### 6.1 亮屏

- 主数字是取整后的米或英尺。单位和「海平面」写在数字下面。
- 精度行：`± 4 m   卫星 + 气压`，颜色点表示优秀 / 良好 / 一般 / 较弱。
- 坐标默认开，时间、地名、精度可关。这些信息留在画面里；隐去的只是按钮，避免拍屏幕时数字跳动位置。
- 没有定位权限或系统定位关闭时，给出说明和按钮，不崩溃。
- 尚无有效海拔时显示「正在寻找卫星」。如果以前存过一次海平面高度，用「上次 …」标出来，不当成实时值。
- 气压计还没被卫星校准前，可以显示气压高度，但文案写明「尚未用卫星校准」，水印上不把它当成海拔（水印写「— —」）。

主题：夜色、纯黑、冰川、暖金、雪地。雪地是浅底，给衣服深、环境亮的时候用。

### 6.2 相机与水印

四种样式，取景和成片共用同一套绘制：

| 样式 | 成片 | 适合 |
| --- | --- | --- |
| 白底 | 照片下方加白底栏 | 默认，最接近那种底栏签名 |
| 黑底 | 同样的底栏，黑底白字 | 夜景、深色衣服 |
| 画框 | 四周留白，文字在底边里 | 像一张装裱过的照片 |
| 浮印 | 不改变画幅，文字浮在画面底部或顶部的渐变上 | 不想改比例时 |

底栏内容固定为两到三行：

```
ALTITUDE ●                         5,210 m
29.65218° N   91.11700° E          2026.10.22  16:42
拉萨
```

红点是我们自己的记号，不是任何相机品牌的标志。底栏高度约为照片宽度的 16.2%（有地名时 21%）。画框左右和上边约为宽度的 4.6%，底边 20%。

保存：

- CameraX `ImageCapture` 取 JPEG，按 `rotationDegrees`（必要时再看 EXIF 方向）转正。
- 在完整分辨率的位图上重画水印，再压成 JPEG。
- `MediaStore` 写入 `Pictures/Altitude`。
- EXIF：纬度、经度、海拔（米，海平面）、时间、`Software=Altitude`。
- 没有海平面海拔时仍然可以拍照，但水印海拔为「— —」，EXIF 不写海拔。没有坐标时不写 GPS EXIF。

### 6.3 海拔

海平面高度 H = 椭球高 h − 大地水准面差距 N。

- API 34+ 且 `hasMslAltitude()` 为真：直接用系统值。
- 否则 N 来自随包的 EGM96 15′ 网格，双线性插值。这个网格的双线性均方误差大约 4 厘米，最大大约 1.2 米，小于手机 GPS 的垂直误差。拉萨附近 N 大约 −35 米，所以椭球高会比路牌海拔矮一截，必须换算。
- 气压高度用国际标准大气对流层公式，它本身不是海平面高度。
- 融合：第一次可靠的 GPS 海平面高度把气压计的零点吸过去。之后短时间的爬升交给气压计；GPS 用大约 12 秒（精度好时）的时间常数慢慢改零点。单次离群点（超过 max(25 m, 3σ)）不拽读数；连续 8 秒都对不上，才重新坐下。GPS 中断后进入「气压延续」，误差随时间变大（每秒 0.15 米，从第 5 秒起算）。
- 垂直精度差于 40 米的点不参与校准。海拔超出 −500–12,000 米的点丢掉。
- 融合逻辑不引用 Android，单元测试在 JVM 上跑。

### 6.4 权限与离线

- 定位：精确定位，拒绝后主界面有入口。
- 相机：可跳过。没相机时亮屏照常。
- 存储：API 29+ 用 MediaStore 自己的集合，不申请写存储。API 26–28 需要 `WRITE_EXTERNAL_STORAGE`。
- `INTERNET` 只给可选的地名。飞行模式下核心功能仍在。
- 没有 Google Play 服务时，退回 `LocationManager` 的 GPS。

## 7. 技术方案

| 层 | 选择 |
| --- | --- |
| 界面 | Kotlin、Jetpack Compose、Material 3、边缘到边缘 |
| 相机 | CameraX 1.6，预览用 TextureView（`COMPATIBLE`），这样浮印能画在预览上面 |
| 定位 | Fused Location 优先，否则 LocationManager |
| 气压 | `Sensor.TYPE_PRESSURE`，没有就只用 GPS |
| 水准面 | `assets/egm96-15.bin`，约 2 MB，小端厘米值 |
| 相册 | MediaStore `Pictures/Altitude` |
| EXIF | AndroidX ExifInterface |
| 版本 | minSdk 26，targetSdk 36。compileSdk 37，因为 Compose 1.12 要求对着 API 37 编译。运行时行为仍按 target 36 |
| 字体 | Outfit（OFL），中文走系统无衬线，避免缺字 |

模块只有 `:app`。纯计算放在 `app.altitude.domain`，不 import Android，测试放在 `app/src/test`。

## 9. 单元测试要锁住的行为

- 1013.25 hPa → 0 m；0 / 1000 / 3650 / 5200 / 8849 m 与气压公式互逆，误差 < 0.05 m。
- 平台已给出 MSL 时不再减 N；否则 H = h − N。没有网格又没有平台值时返回空。
- 只有 GPS：第一点贴住，1 秒内向新值走大约 70%，不一步跳完（精度 5 m，时间常数 0.8 s）。
- 只有气压：有数字，但 `absoluteMsl == false`。
- GPS + 气压：第一点把零点吸到 GPS。之后 0.5 秒气压升高 10 米且没有新 GPS，读数跟着升高约 10 米。
- 2 秒内 GPS 偏 20 米：读数只挪几米，不到 6 米。
- 单次偏 80 米：读数不动。连续到第 8 秒：零点重坐，读数到新的 GPS。
- GPS 中断 10 秒：来源变为气压延续，高度跟着气压，精度在原来的 4 m 上加 0.75 m。
- 20 km 的荒谬高度被丢掉。
- 5,210 m = 17,093 ft。坐标格式 `29.65200° N`。上海时区水印时间 `2026.10.22  16:42`。
- 白底底栏不改变照片宽度，高度增加 486 px（宽 3000）。画框输出 3276×4738（原图 3000×4000）。取景框装进可用区域且保持 3:4。

构建：

- [x] `./gradlew :app:testDebugUnitTest` 通过（23 个用例，2026-10-22）

模拟器（API 35，Google APIs）：

- [ ] 安装后先看到引导，而不是白屏或崩溃
- [ ] 注入拉萨附近坐标后，亮屏出现三千米以上的海平面高度，而不是椭球高原样
- [ ] 竖屏数字可辨；切换到相机后能看到底栏水印和快门
- [ ] 拍一张，JPEG 里能看见水印；EXIF 有纬度和经度，海拔字段有值
- [ ] 横屏不把布局裁破

已知模拟器限制写在 README：没有气压计，相机是虚拟场景，GPS 要手动注入。真机才会同时看到「卫星 + 气压」。

## 11. 风险

- EGM96 15′ 在地形剧烈处最大约 1.2 米。手机垂直精度通常更大，这个误差可以接受，但不要把它说成测量级。
- 模拟器 `geo fix` 的高度进的是 `Location.getAltitude()`。若系统不提供 MSL，本应用会再减 N。拉萨会因此比注入值高大约 35 米，这是正确行为。
- 部分机型没有气压计。读数仍然可用，只是不会写「气压」。
- 地名依赖 Geocoder，离线经常为空。
- CameraX 在模拟器上可能没有相机。界面仍要能说明原因，不能崩。
